# UDRP 案例库 · 待采集清单与采集规范

> 本文件不对外发布（位于 `_internal/`，Jekyll 构建时排除）。
> 配套数据模型见同目录 `schema.json`；发布模板见 `udrp/cases/_templates/case.html`；列表页框架见 `udrp/cases/index.html`（已设 noindex，未加入 sitemap）。

## 一、采集铁律

1. **只采官方来源**：裁决全文必须来自作出裁决的机构官方网站。不使用第三方转载、数据库镜像、律所公众号改写稿作为事实来源。
2. **逐字核对**：案号、裁决日期、当事人名称、争议域名、裁决结果，四项必须与官方裁决全文首页记载逐字一致。任何一项无法确认即不录入。
3. **不推断、不补全**：裁决未写明的内容（例如当事人所在地、域名取得价格）一律留空，不依据域名后缀或名称推测。
4. **不评价**：摘要只陈述裁决记载的事实与认定，不添加"该案说明……"式的引申结论；引申性分析另写文章，与案例条目分开。
5. **sourceVerified 为 true 才可发布**：`published` 字段在 `sourceVerified` 为 false 时不得置为 true。
6. **宁缺毋滥**：本轮及后续均以"可核实的少量案例"优先于"不可核实的大量案例"。

按"与中国主体相关度 × 实务参考价值"排序，而非按案件知名度排序。

## 五、单条案例的录入步骤

1. 在机构官网检索并打开裁决全文页面，记录 URL。
2. 新建条目文件，或在数据文件中追加对象，按 `schema.json` 逐字段填写。
3. 逐字核对 `caseNumber`、`decisionDate`、`complainant`、`respondent`、`disputedDomains`、`result` 六项。
4. 填写 `threeElements`，只按裁决实际认定填写；未认定填 `not-reached`。
5. 填写 `policyParagraphs` / `rulesParagraphs`，只填裁决实际援引的条款编号。
6. `sourceVerified` 置为 `true`，`sourceVerifiedDate` 填实际核对日期。
7. 按 `udrp/cases/_templates/case.html` 生成页面，`published` 置为 `true`。
8. 重新运行站点校验脚本，确认链接与结构化数据无误。
